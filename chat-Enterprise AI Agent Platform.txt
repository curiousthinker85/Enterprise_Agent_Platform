### 💻 Let's Write the First Piece of Code: The Model Gateway

To prove the "plugin" concept immediately, here is the foundational FastAPI code for your **Unified Model Gateway**. This allows the client to switch between a local Ollama model and an OpenAI model seamlessly.

*First, install dependencies:* `pip install fastapi uvicorn litellm pydantic`

```python
# main.py
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from litellm import completion
import os

app = FastAPI(title="Enterprise AI Agent Gateway")

# Configuration model (This is what the client "plugins" in)
class ModelConfig(BaseModel):
    provider: str  # e.g., "openai", "ollama", "azure"
    model_name: str  # e.g., "gpt-4o", "llama3", "azure/gpt-4"
    api_key: str | None = None  # Optional for local models
    api_base: str | None = None  # Required for local Ollama/vLLM (e.g., "http://localhost:11434")

class ChatRequest(BaseModel):
    messages: list[dict]  # [{"role": "user", "content": "Compare these two docs..."}]
    config: ModelConfig
    workspace_id: str  # For future RBAC/logging

@app.post("/api/v1/chat")
async def chat_endpoint(request: ChatRequest):
    try:
        # LiteLLM standardizes the call across ALL providers
        response = completion(
            model=request.config.model_name,
            messages=request.messages,
            api_key=request.config.api_key,
            api_base=request.config.api_base,
            temperature=0.1 # Low temperature for HR/Finance accuracy
        )
        
        return {
            "success": True,
            "response": response.choices[0].message.content,
            "model_used": response.model,
            "workspace_id": request.workspace_id
        }
    except Exception as e:
        raise HTTPException(status_code=500, detail=f"Model inference failed: {str(e)}")

# Run with: uvicorn main:app --reload
```

**Why this is powerful:** Your entire platform's frontend and agent logic only ever talks to *this* `/api/v1/chat` endpoint. If the client wants to switch from OpenAI to a locally hosted Qwen model for data privacy, they just change the `provider`, `model_name`, and `api_base` in the config. The rest of your platform doesn't need to change a single line of code.

```python
    request_timeout_seconds: int = 60

    @property
    def is_production(self) -> bool:
        return self.environment == "prod"


@lru_cache
def get_settings() -> Settings:
    """
    Cached settings loader.

    Why lru_cache?
    --------------
    We do not want to read and parse .env repeatedly for every request.
    This function loads settings once and reuses them.
    """
    return Settings()
```

## Why this design?

We use a `Settings` class because:

- environment variables become typed Python fields
- mistakes are caught early
- secrets are not scattered across files
- deployment becomes easier

Example:

```env
DEFAULT_LLM_MODEL=gpt-4o-mini
```

becomes:

```python
settings.default_llm_model
```

instead of unsafe:

```python

from typing import Any, Literal

from pydantic import BaseModel, Field


class ChatMessage(BaseModel):
    """
    Single chat message.

    Why validate role?
    ------------------
    LLM providers expect roles like:
    - system
    - user
    - assistant

    If invalid role comes, we reject it before calling the model.
    This saves cost and prevents confusing provider errors.
    """

    role: Literal["system", "user", "assistant"]
    content: str


class ChatRequest(BaseModel):
    """
    Incoming chat request.

    Design decision:
    ----------------
    For MVP, model can be overridden per request.

    In production enterprise version:
    - API keys should not come from every request
    - model profiles should be stored securely
    - users should select a permitted model profile
    """

    messages: list[ChatMessage] = Field(..., min_length=1)
    model: str | None = None
    temperature: float | None = Field(default=None, ge=0, le=2)
    max_tokens: int | None = Field(default=None, gt=0)
    metadata: dict[str, Any] = Field(default_factory=dict)


class Usage(BaseModel):
    """
    Token usage information.

    Why track usage?
    ----------------
    Enterprises need cost visibility.
    Later we can show:
    - tokens used by HR workspace
    - tokens used by finance audit workspace
    - model-wise cost estimates
    """

    prompt_tokens: int | None = None
    completion_tokens: int | None = None
    total_tokens: int | None = None


class ChatResponse(BaseModel):
    """
    Standardized chat response.

    Why standardize?
    ----------------
    Whether the client uses OpenAI, Ollama, Azure, or Anthropic,
    our frontend should receive the same response shape.
    """

    id: str | None = None
    model: str
    content: str
    usage: Usage | None = None
    provider: str | None = None


class ModelTestResponse(BaseModel):
    ok: bool
    model: str
    message: str
```

## Why schemas are important

Schemas act like a contract.

They answer:

- What input is allowed?
- What output will the client receive?
- What should be validated?
- What should be rejected?

Example:

If someone sends:

```json
{
  "messages": []
}
```

FastAPI rejects it because:

```python
min_length=1
```

This protects the LLM gateway from useless calls.

# 4. LLM Gateway Service

Create:

```text
backend/app/services/llm_gateway.py
```

Code:

```python
import logging
from typing import Any

import litellm
from litellm import acompletion

from app.core.config import Settings, get_settings
from app.schemas.chat import ChatRequest, ChatResponse, Usage


logger = logging.getLogger(__name__)

# Useful for provider compatibility.
# If a provider does not support a parameter, LiteLLM can drop it instead of failing.
litellm.drop_params = True


class LLMGatewayError(Exception):
    """
    Custom exception for model gateway failures.

    Why custom exception?
    ---------------------
    We want to separate infrastructure/model errors from normal validation errors.
    Later, routes can convert this into proper HTTP 502/503 responses.
    """

    pass


class LLMGateway:
    """
    Bring Your Own Model gateway.

    Responsibility:
    ---------------
    Convert our internal chat request into a provider-compatible LLM call.

    This is the heart of your platform's plugin idea.
    """

    def __init__(self, settings: Settings | None = None) -> None:
        self.settings = settings or get_settings()

    def _build_kwargs(self, request: ChatRequest) -> dict[str, Any]:
        """
        Build LiteLLM keyword arguments.

        Why separate method?
        --------------------
        This makes the code testable.
        We can test request-to-provider mapping without actually calling OpenAI/Ollama.
        """

        model = request.model or self.settings.default_llm_model

        if not model:
            raise LLMGatewayError(
                "No model configured. Please set DEFAULT_LLM_MODEL or provide model in request."
            )

        kwargs: dict[str, Any] = {
            "model": model,
            "messages": [message.model_dump() for message in request.messages],
            "temperature": (
                request.temperature
                if request.temperature is not None
                else self.settings.llm_temperature
            ),
            "timeout": self.settings.request_timeout_seconds,
        }

        max_tokens = (
            request.max_tokens
            if request.max_tokens is not None
            else self.settings.llm_max_tokens
        )

        if max_tokens:
            kwargs["max_tokens"] = max_tokens

        if self.settings.default_llm_api_key:
            kwargs["api_key"] = self.settings.default_llm_api_key

        if self.settings.default_llm_api_base:
            kwargs["api_base"] = self.settings.default_llm_api_base

        if self.settings.default_llm_api_version:
            kwargs["api_version"] = self.settings.default_llm_api_version

        return kwargs

    async def chat(self, request: ChatRequest) -> ChatResponse:
        """
        Send chat request to configured model.

        Flow:
        -----
        1. Build provider kwargs
        2. Call LiteLLM async completion
        3. Normalize response
        4. Return standard ChatResponse
        """

        kwargs = self._build_kwargs(request)
        model = kwargs["model"]

        logger.info("Calling LLM gateway | model=%s", model)

        try:
            response = await acompletion(**kwargs)
        except Exception as exc:
            logger.exception("LLM gateway call failed | model=%s", model)
            raise LLMGatewayError(str(exc)) from exc

        choice = response.choices[0]
        content = choice.message.content or ""

        usage_raw = getattr(response, "usage", None)
        usage = None

        if usage_raw:
            usage = Usage(
                prompt_tokens=getattr(usage_raw, "prompt_tokens", None),
                completion_tokens=getattr(usage_raw, "completion_tokens", None),
                total_tokens=getattr(usage_raw, "total_tokens", None),
            )

        return ChatResponse(
            id=getattr(response, "id", None),
            model=getattr(response, "model", model),
            content=content,
            usage=usage,
            provider=self.settings.default_llm_provider,
        )


_gateway: LLMGateway | None = None


def get_gateway() -> LLMGateway:
    """
    Dependency provider for FastAPI.

    Why singleton-style?
    --------------------
    We do not need to recreate gateway object for every request.
    Later this can be extended with connection pooling, retry policy, metrics, etc.
    """

    global _gateway

    if _gateway is None:
        _gateway = LLMGateway()

    return _gateway
```

## Why this file is important

This is your platform’s **model plugin layer**.

Later, when you add:

- Ollama
- vLLM
- OpenAI
- Azure OpenAI
- AWS Bedrock
- Anthropic

most of your application should continue working because they all go through this gateway.

```python
from contextlib import asynccontextmanager

from fastapi import FastAPI, Request
from fastapi.middleware.cors import CORSMiddleware
from fastapi.responses import JSONResponse

from app.api.routes import health, models
from app.core.config import get_settings
from app.core.logging import configure_logging
from app.services.llm_gateway import LLMGatewayError


@asynccontextmanager
async def lifespan(app: FastAPI):
    """
    Lifespan events.

    Why use lifespan?
    -----------------
    This is the modern FastAPI way to run startup/shutdown logic.

    Currently:
    - configure logging on startup

    Later:
    - connect database
    - initialize vector store
    - warm up model clients
    - load document parsers
    """

    configure_logging()
    yield


def create_app() -> FastAPI:
    settings = get_settings()

    app = FastAPI(
        title=settings.app_name,
        version=settings.app_version,
        lifespan=lifespan,
    )

    app.add_middleware(
        CORSMiddleware,
        allow_origins=settings.cors_origins,
        allow_credentials=True,
        allow_methods=["*"],
        allow_headers=["*"],
    )

    app.include_router(health.router, prefix="/api/v1")
    app.include_router(models.router, prefix="/api/v1")

    @app.exception_handler(LLMGatewayError)
    async def llm_gateway_error_handler(request: Request, exc: LLMGatewayError):
        """
        Convert gateway errors into proper HTTP responses.

        Why?
        ----
        Clients should not receive raw Python exceptions.
        They should receive structured API errors.
        """

        return JSONResponse(
            status_code=502,
            content={
                "detail": str(exc),
                "path": str(request.url.path),
            },
        )

    return app


app = create_app()
```

# Common Mistakes to Avoid

## Mistake 1: Putting model logic inside route

Bad:

```python
@router.post("/chat")
async def chat(...):
    response = await acompletion(...)
```

Good:

```python
@router.post("/chat")
async def chat(...):
    return await gateway.chat(request)
```

Why?

Routes should handle HTTP.
Services should handle business logic.

---

## Mistake 2: Reading env variables everywhere

Bad:

```python
os.getenv("DEFAULT_LLM_MODEL")
```

Good:

```python
settings.default_llm_model
```

Why?

Typed, centralized, testable configuration.

---

## Mistake 3: Returning API keys in API response

Never do this:

```json
{
  "api_key": "sk-..."
}
```

Only return:

```json
{
  "api_key_configured": true
}
```

---

## Mistake 4: Using high temperature for HR/Finance

Bad:

```env
LLM_TEMPERATURE=1.2
```

Good:

```env
LLM_TEMPERATURE=0.1
```
